## 1. System monitoring — CPU, RAM, and disk usage (`1-psutil.py`)

```bash
python -m pip install psutil
```

```python
import psutil

cpu_usage = psutil.cpu_percent(interval=1)
print(f"CPU Usage: {cpu_usage}%")

memory_info = psutil.virtual_memory()
print(f"Memory information: {memory_info}")

memory_percent = psutil.virtual_memory().percent
print(f"Memory Usage percentage: {memory_percent}%")

disk_usage = psutil.disk_usage('/')
print(f"Disk Usage: {disk_usage.percent}%")
```
**Sample output** (exact numbers depend entirely on the machine — this is illustrative, not a fixed result):
```
CPU Usage: 12.5%
Memory information: svmem(total=17032704000, available=8234567680, percent=51.7, used=8798136320, free=8234567680)
Memory Usage percentage: 51.7%
Disk Usage: 63.0%
```
- `psutil.cpu_percent(interval=1)` — the `interval=1` makes it **wait one second** and measure CPU usage over that window, which gives a far more accurate reading than calling it with no interval (which compares against whatever the last call happened to be).
- `psutil.virtual_memory()` returns a whole bundle of memory stats at once (`total`, `available`, `percent`, `used`, `free`) — `.percent` on its own, like `psutil.disk_usage('/').percent`, pulls out just the one number you usually actually want.

## 2. Managing a systemd service (`2-service-mange.py`)

```python
import os
import sys

def start_service(service_name):
    os.system(f"sudo systemctl start {service_name}")
    print(f"Service {service_name} started")

def stop_service(service_name):
    os.system(f"sudo systemctl stop {service_name}")
    print(f"Service {service_name} stopped")

def status_service(service_name):
    os.system(f"sudo systemctl status {service_name}")
    print(f"Service {service_name} status")


service_name = "jenkins"
# service_name = input("Enter service name: ")
# service_name = sys.argv[1]

start_service(service_name)
status_service(service_name)
stop_service(service_name)
```
- Three small, reusable functions wrapping `systemctl start`/`status`/`stop` — this is the same `os.system(f"...")` pattern already used for `ping` (`19.3November_Python_Modules_RealTimeUseCases.md` §2).
- `service_name` is hardcoded here (`"jenkins"`), with the commented-out lines showing the two other ways to supply it — interactively via `input()`, or from the command line via `sys.argv[1]` (`19.1November_Python_EnvVars_CLIArgs.md`).
- ⚠️ Each `sudo systemctl ...` call needs the user running the script to actually have `sudo` rights — on a machine where `sudo` prompts for a password, `os.system()` would hang waiting for interactive input it never gets, since there's no terminal prompt wired up here.

## 3. Listing Docker containers

```python
import os

os.system("docker ps")

print("Listed all running Docker containers")
```
- `docker ps` lists only **running** containers. `docker ps -a` (not shown here) would list every container, including stopped ones — worth knowing the difference if the output looks shorter than expected.

## 4. Creating an EC2 instance with `boto3`

```python
import boto3

def create_ec2_instance():
    ec2 = boto3.resource('ec2')

    instance = ec2.create_instances(
        ImageId='ami-0abcdef1234567890',  # Replace with a valid AMI ID
        MinCount=1,
        MaxCount=1,
        InstanceType='t2.micro',
        KeyName='your-key-pair-name'  # Replace with your key pair name
    )

    print(f'Created EC2 Instance with ID: {instance[0].id}')


if __name__ == "__main__":
    create_ec2_instance()
```
- `boto3.resource('ec2')` — the higher-level, object-oriented `boto3` interface (as opposed to `boto3.client('ec2')`, the lower-level one used for the cleanup scripts in `21.2November_Python_InterviewQA.md` §11).
- `create_instances(...)` always returns a **list** of instance objects, even when `MaxCount=1` only creates one — that's why it's `instance[0].id`, not just `instance.id`.
- `ImageId` and `KeyName` are placeholders here — a real run needs a genuine AMI ID for the target region and a key pair that actually exists in your AWS account.

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| `psutil.cpu_percent(interval=1)` | Waits 1 second, then reports accurate CPU usage | More reliable than calling it with no interval |
| `psutil.virtual_memory().percent` | Just the memory-usage percentage, not the whole bundle | Quick health-check number for an alert |
| `systemctl start/stop/status` via `os.system()` | Managing a service from a Python script | Restarting Jenkins from an automation script |
| `docker ps` vs `docker ps -a` | Running containers only, vs every container | Don't be surprised when a stopped container is missing |
| `boto3.resource('ec2').create_instances()` | Returns a **list**, even for one instance | `instance[0].id`, not `instance.id` |
| `boto3.resource()` vs `boto3.client()` | Higher-level/object-oriented vs lower-level | Both valid — pick based on what the task needs |
