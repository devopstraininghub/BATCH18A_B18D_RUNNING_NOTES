## 1. While loops

**Shell (`1-while.sh`):**
```bash
#!/bin/bash

num=1
while [ $num -le 100 ]
do
  echo "THE VALUE OF NUMBER IS $num"

  num=$((num + 1))

done

echo "Done with printing numbers from 1 to 100"
```

**Python (`2-while.py`):**
```python
num = 1
while num <= 100:
    print(f"THE VALUE OF NUMBER IS {num}")
    num = num + 1

print("Done with printing numbers from 1 to 100")
```
**Sample output** (both versions — truncated, since this runs 100 times, `num = 1` through `num = 100`):
```
THE VALUE OF NUMBER IS 1
THE VALUE OF NUMBER IS 2
...
THE VALUE OF NUMBER IS 100
Done with printing numbers from 1 to 100
```

## 2. `break` and `continue`

- **`break`** — exits the loop immediately, for good. Nothing after it in the loop runs again.
- **`continue`** — skips just the **rest of the current iteration**, then goes straight back to re-checking the loop's condition for the next one.

**`break` example (`3-break.py`):**
```python
num = 1
while num <= 100:
    print(f"THE VALUE OF NUMBER IS {num}")

    if num == 5:
        print("BREAKING THE LOOP AS NUMBER IS 5")
        break

    num = num + 1

print("Done with printing numbers from 1 to 5 as we have broken the loop when number is 5")
```
**Sample output:**
```
THE VALUE OF NUMBER IS 1
THE VALUE OF NUMBER IS 2
THE VALUE OF NUMBER IS 3
THE VALUE OF NUMBER IS 4
THE VALUE OF NUMBER IS 5
BREAKING THE LOOP AS NUMBER IS 5
Done with printing numbers from 1 to 5 as we have broken the loop when number is 5
```
- The loop never reaches `num = 100` at all — `break` stops it dead at `num = 5`.

**`continue` example (`4-continue.py`):**
```python
i = 1

while i <= 100:

    if i == 5:
        i = i + 1
        continue

    print("Iteration number:", i)

    i = i + 1

print("Loop finished!")
```
**Sample output** (truncated — the loop still runs all the way to `i = 100`, it just never prints `5`):
```
Iteration number: 1
Iteration number: 2
Iteration number: 3
Iteration number: 4
Iteration number: 6
Iteration number: 7
...
Iteration number: 100
Loop finished!
```
- ⚠️ The key difference from `break`: **`continue` doesn't stop the loop** — it only skips printing on the one iteration where `i == 5`, then keeps going all the way to 100 like normal.

**Easy memory trick:** `break` = **leave the building**. `continue` = **skip this one step, keep walking**.

## 3. For loops

- A `for` loop walks through every item in a list (or any other iterable), one at a time.

```python
for variable in iterable:
    # Block of code to execute
```

**Looping over a list directly (`5-for.py`):**
```python
my_list = [1, 2, 3, 4, 5]

for i in my_list:
    print(f"The value of variable i in current iteration is {i}")
```
**Sample output:**
```
The value of variable i in current iteration is 1
The value of variable i in current iteration is 2
The value of variable i in current iteration is 3
The value of variable i in current iteration is 4
The value of variable i in current iteration is 5
```

**Looping over a `range()` instead of a real list (`6-range.py`):**
```python
for i in range(50, 100):
    print(f"Iteration number & value of i is {i}")
```
**Sample output** (truncated — `range(50, 100)` runs `i = 50` through `i = 99`, 50 numbers total):
```
Iteration number & value of i is 50
Iteration number & value of i is 51
...
Iteration number & value of i is 99
```
- ⚠️ **`range(k, n)` stops one short of `n`.** `range(50, 100)` gives `50` up to `99` — it never reaches `100`. This trips up almost everyone the first time.

**Looping over a list of strings (`7-fruits.py`):**
```python
fruits_list = ["apple", "banana", "cherry", "kiwi", "mango"]

for fruit in fruits_list:
    print(f"The current fruit is {fruit}")
```
**Sample output:**
```
The current fruit is apple
The current fruit is banana
The current fruit is cherry
The current fruit is kiwi
The current fruit is mango
```

## 4. Lambda functions (`8-lamda.py`)

- A **lambda** is a small, **anonymous** function — defined in one line with the `lambda` keyword, with no `def` and no name of its own (though you can still assign it to a variable, as below).

```
lambda arguments: expression
```
- `lambda` — the keyword that starts it.
- `arguments` — the input parameters, same idea as a normal function's parameters.
- `expression` — a single expression, whose result is automatically returned (no `return` keyword needed).

**The same logic, written the normal way first, for comparison:**
```python
def sum(a, b):
    return a + b

result = sum(10, 20)
print(f"The sum of 10 and 20 is {result}")
```

**Now as a lambda — one line instead of three:**
```python
sum = lambda a, b: a + b

print(f"The sum of 10 and 20 is {sum(10, 20)}")

multiply = lambda a, b: a * b
print(f"The product of 10 and 20 is {multiply(10, 20)}")
```
**Sample output:**
```
The sum of 10 and 20 is 30
The product of 10 and 20 is 200
```
- Note: same as in `16.2November_Python_Functions.md`'s `4-sum.py` — naming this `sum` **shadows** Python's built-in `sum()` function for the rest of this script. Fine here, since nothing else needs the real `sum()`, but worth being deliberate about.
- A lambda is best for a short, throwaway expression used once (e.g. as a `sort()` key) — anything longer or reused in several places is clearer as a normal `def` function.

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| `while` loop | Repeats while a condition stays `True` | Polling a service's health check until it's ready |
| `break` | Exits the loop immediately | Stop retrying once a connection succeeds |
| `continue` | Skips just this iteration, keeps looping | Skip a malformed log line, keep processing the rest |
| `for x in list` | Walks through every item once | Running the same check against every server in a list |
| `range(k, n)` | Stops **before** `n` — `range(50, 100)` is `50`–`99` | `range(len(my_list))` for index-based looping |
| `lambda` | A one-line, unnamed function, equivalent to a tiny `def` | A quick `sort(key=lambda x: x[1])`-style helper |
