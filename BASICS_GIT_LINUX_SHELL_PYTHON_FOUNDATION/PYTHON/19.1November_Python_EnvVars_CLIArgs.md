# Batch 18 — Running Notes: 19 November 2026

**Topic: Environment Variables and Command-Line Arguments**

Friends, two ways to feed a script information **from outside the code itself**, without hardcoding it — environment variables, and command-line arguments.

---

## 1. What is an environment variable?

- A value stored in the system environment, outside any one program.
- Available system-wide, and automatically inherited by child processes.
- Used to pass configuration or secrets **without hardcoding them in the program.**

**Why they matter:**
- Used for API keys, passwords, tokens.
- Used in CI/CD pipelines.
- Used in Docker, Kubernetes, Terraform.
- Keeps code secure and configurable.
- Avoids hardcoding of sensitive data.

**Setting one, per OS:**
```bash
# Unix/Linux/macOS
export MY_ENV_VARIABLE="some_value"
```
```cmd
:: Windows
set MY_VARIABLE=some_value
```

**Reading one in Python:**
```python
import os

user = os.getenv('USERNAME')
awsvar = os.getenv('MY_VARIABLE')

print(f"user env variable is : {user}")
print(f"aws variable is: {awsvar}")
```
**Sample output** (on a Windows machine logged in as `Madhukiran`, with `MY_VARIABLE` not set):
```
user env variable is : Madhukiran
aws variable is: None
```
- `os.getenv(name)` returns `None` if the variable doesn't exist — it never crashes, unlike `os.environ[name]` (square-bracket access), which raises a `KeyError` on a missing key, the same safe-vs-unsafe-lookup distinction already seen with `dict.get()` (`17.1November_Python_Collections_Methods.md` §4).
- ⚠️ `USERNAME` is the **Windows** convention for the logged-in user's name. On Linux/macOS, the equivalent environment variable is `USER` (sometimes `LOGNAME`) — `os.getenv('USERNAME')` on Linux would just return `None`.

## 2. Command-line arguments — `sys.argv`

- Command-line arguments are values passed to a script when it's run from the terminal, letting users supply input dynamically without touching the code.

```bash
py script.py arg1 arg2 arg3
```

- `sys.argv` is a **list**, provided by the `sys` module, holding every command-line argument the script was run with.

```python
import sys
print(sys.argv)
```
**Running** `python3 test.py madhu 123` **gives:**
```
['test.py', 'madhu', '123']
```

**Index breakdown:**

| Index | Holds |
|---|---|
| `sys.argv[0]` | Always the script's own name (e.g. `"test.py"`) |
| `sys.argv[1]` | The first real argument |
| `sys.argv[2]` | The second real argument |
| `sys.argv[n]` | The `n`th argument |

**A script using two arguments (`my_script.py`):**
```python
import sys

env_name = sys.argv[1]
rel_number = sys.argv[2]

print(f"The environment to deploy:  {env_name} ")
print(f"The Release version is :  {rel_number} ")
```
**Running** `python3 my_script.py env rel_number`**:**
```
The environment to deploy:  env 
The Release version is :  rel_number 
```
- Real DevOps use: `python3 my_script.py prod 2.5.1` — a deploy script that takes the target environment and release version straight from the command line, instead of editing the script itself every time.

**Combining environment variables and command-line arguments (`combined_script.py`):**
```python
import os
import sys

user = os.getenv('USERNAME')
file_path = sys.argv[1]

print(f"user env variable is : {user}")
print(f"File Path: {file_path}")
```
**Running** `python3 combined_script.py C:\logs\app.log` **on the same Windows machine:**
```
user env variable is : Madhukiran
File Path: C:\logs\app.log
```

**Easy memory trick:** Environment variables are **ambient** — set once, read by anything running in that shell. Command-line arguments are **per-run** — supplied fresh, every single time the script is called.

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| Environment variable | A value available system-wide, inherited by child processes | An API key or DB password, kept out of the code |
| `os.getenv(name)` | Reads an env var; returns `None` if missing — never crashes | Safer than `os.environ[name]`, which raises `KeyError` |
| `USERNAME` vs `USER` | Windows vs Linux/macOS convention for the logged-in user | `os.getenv('USERNAME')` is `None` on Linux |
| `sys.argv` | A list of every command-line argument, `argv[0]` is the script name | `python3 deploy.py prod 2.5.1` → `argv[1]='prod'`, `argv[2]='2.5.1'` |
