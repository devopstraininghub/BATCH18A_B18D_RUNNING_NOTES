# Batch 18 — Running Notes: 19 November 2026

**Topic: Environment Variables and Command-Line Arguments**

Friends, two ways to feed a script information **from outside the code itself**, without hardcoding it — environment variables, and command-line arguments.

---

## 1. What is an environment variable?

- A value stored in the system environment, outside any one program.
- Available system-wide, and automatically inherited by child processes.
- Used to pass configuration or secrets **without hardcoding them in the program.**

**Why they matter:**
- Used for API keys, passwords, tokens.
- Used in CI/CD pipelines.
- Used in Docker, Kubernetes, Terraform.
- Keeps code secure and configurable.
- Avoids hardcoding of sensitive data.

**Setting one, per OS:**
```bash
# Unix/Linux/macOS
export MY_ENV_VARIABLE="some_value"
```
```cmd
:: Windows
set MY_VARIABLE=some_value
```

**Reading one in Python (`1.py`):**
```python
import os

user = os.getenv('USERNAME')
mcvariable = os.getenv('MC_VAR2')

print(f"USER NAME IS {user}")
print(f"MC VARIABLE IS {mcvariable}")
```
**Sample output** (on a Windows machine logged in as `Madhukiran`, with `MC_VAR2` not set in this shell):
```
USER NAME IS Madhukiran
MC VARIABLE IS None
```
- `os.getenv(name)` returns `None` if the variable doesn't exist — it never crashes, unlike `os.environ[name]` (square-bracket access), which raises a `KeyError` on a missing key, the same safe-vs-unsafe-lookup distinction already seen with `dict.get()` (`17.1November_Python_Collections_Methods.md` §4).
- ⚠️ `USERNAME` is the **Windows** convention for the logged-in user's name. On Linux/macOS, the equivalent environment variable is `USER` (sometimes `LOGNAME`) — `os.getenv('USERNAME')` on Linux would just return `None`.

## 2. Command-line arguments — `sys.argv`

- Command-line arguments are values passed to a script when it's run from the terminal, letting users supply input dynamically without touching the code.

```bash
py script.py arg1 arg2 arg3
```

- `sys.argv` is a **list**, provided by the `sys` module, holding every command-line argument the script was run with.

```python
import sys
print(sys.argv)
```
**Running** `python3 test.py madhu 123` **gives:**
```
['test.py', 'madhu', '123']
```

**Index breakdown:**

| Index | Holds |
|---|---|
| `sys.argv[0]` | Always the script's own name (e.g. `"test.py"`) |
| `sys.argv[1]` | The first real argument |
| `sys.argv[2]` | The second real argument |
| `sys.argv[n]` | The `n`th argument |

**A deploy script using two arguments (`3-sys.py`):**
```python
import sys

env_name = sys.argv[1]
release_name = sys.argv[2]

print(f"Script name is {sys.argv[0]}")

print(f"Environment name is {env_name}")
print(f"Release name is {release_name}")

######### logic to deploy the release in the environment ############
######## code & logic
######

print(f"Release {release_name} is deployed in {env_name} environment successfully")
```
**Running** `python3 3-sys.py prod 2.5.1`**:**
```
Script name is 3-sys.py
Environment name is prod
Release name is 2.5.1
Release 2.5.1 is deployed in prod environment successfully
```
- Real DevOps use: this is the shape of a real deploy script — the target environment and release version come straight from the command line, instead of editing the script itself every time. The `#####` comment block is a placeholder standing in for the real deploy logic that would actually go there.

**Arguments aren't limited to text — convert them to use in a calculation (`2.cla.py`):**
```python
import sys

def add(a, b):
    output = a + b
    print(f"Addition of {a} and {b} is {output}")


num1 = int(sys.argv[1])
num2 = int(sys.argv[2])

print(f"Script name is {sys.argv[0]}")

print(f"First number is {num1}")
print(f"Second number is {num2}")

add(num1, num2)
```
**Running** `python3 2.cla.py 10 20`**:**
```
Script name is 2.cla.py
First number is 10
Second number is 20
Addition of 10 and 20 is 30
```
- ⚠️ Every entry in `sys.argv` is always a **string**, even if it looks like a number — `sys.argv[1]` here is the string `"10"`, not the int `10`. Skipping the `int(...)` wrap would make `num1 + num2` **concatenate** the two strings (`"10" + "20"` → `"1020"`) instead of adding them — the same str-vs-number mistake already seen with `input()` (`13November_Python.md` §7).

**Guarding against missing arguments, before using them (`9-sysmodule.py`):**
```python
import sys

if len(sys.argv) < 3:
    print("Warning: no proper arguments provided.")
    print("Usage: py script.py <num1> <num2>")
    sys.exit(1)

num1 = sys.argv[1]
num2 = sys.argv[2]

print(f"Sum of {num1} and {num2} is: {int(num1) + int(num2)}")
```
**Running** `python3 9-sysmodule.py` **with no arguments at all:**
```
Warning: no proper arguments provided.
Usage: py script.py <num1> <num2>
```
- `len(sys.argv)` is `1` when no real arguments were given (just the script name itself) — checking `< 3` catches the case where fewer than 2 real arguments (`argv[1]`/`argv[2]`) were supplied.
- `sys.exit(1)` stops the script immediately, with a **non-zero exit code** — the standard way a script signals "something went wrong" to whatever called it (a CI/CD pipeline step, a shell script, another program). `sys.exit(0)`, or no argument at all, signals success.

**Combining environment variables and command-line arguments (`combined_script.py`):**
```python
import os
import sys

user = os.getenv('USERNAME')
file_path = sys.argv[1]

print(f"user env variable is : {user}")
print(f"File Path: {file_path}")
```
**Running** `python3 combined_script.py C:\logs\app.log` **on the same Windows machine:**
```
user env variable is : Madhukiran
File Path: C:\logs\app.log
```

**Easy memory trick:** Environment variables are **ambient** — set once, read by anything running in that shell. Command-line arguments are **per-run** — supplied fresh, every single time the script is called.

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| Environment variable | A value available system-wide, inherited by child processes | An API key or DB password, kept out of the code |
| `os.getenv(name)` | Reads an env var; returns `None` if missing — never crashes | Safer than `os.environ[name]`, which raises `KeyError` |
| `USERNAME` vs `USER` | Windows vs Linux/macOS convention for the logged-in user | `os.getenv('USERNAME')` is `None` on Linux |
| `sys.argv` | A list of every command-line argument, `argv[0]` is the script name | `python3 deploy.py prod 2.5.1` → `argv[1]='prod'`, `argv[2]='2.5.1'` |
| `sys.argv` entries are always strings | Wrap in `int()`/`float()` before doing math | Skipping it turns `+` into string concatenation |
| `len(sys.argv)` + `sys.exit(1)` | Validate enough arguments were given, exit with a non-zero code if not | A deploy script refusing to run with missing arguments |
