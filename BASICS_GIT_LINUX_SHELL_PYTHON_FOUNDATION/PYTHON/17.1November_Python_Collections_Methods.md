## 1. List operations (`1-list-ops.py`)

**Complete script:**
```python
my_list = [1, 2, 3, 1, 4, 5]

my_list.append(4)
print("After append:", my_list)

my_list.extend([8, 9, 7])
print("After extend:", my_list)

my_list.insert(0, 10)
print("After insert:", my_list)

my_list.remove(1)
print("After remove:", my_list)

popped_element = my_list.pop()
print("Popped element:", popped_element)
print("After pop:", my_list)

index_of_9 = my_list.index(9)
print("Index of 9:", index_of_9)

count_of_1 = my_list.count(1)
print("Count of 1:", count_of_1)

my_list.sort()
print("After sort:", my_list)

my_list.reverse()
print("After reverse:", my_list)

copied_list = my_list.copy()
print("Copied list:", copied_list)

my_list.clear()
print("After clear:", my_list)

print("Length of list:", len(my_list))
print("Length of copied list:", len(copied_list))
print("Maximum:", max(copied_list))
print("Minimum:", min(copied_list))
print("Sum:", sum(copied_list))
```

**Sample output:**
```
After append: [1, 2, 3, 1, 4, 5, 4]
After extend: [1, 2, 3, 1, 4, 5, 4, 8, 9, 7]
After insert: [10, 1, 2, 3, 1, 4, 5, 4, 8, 9, 7]
After remove: [10, 2, 3, 1, 4, 5, 4, 8, 9, 7]
Popped element: 7
After pop: [10, 2, 3, 1, 4, 5, 4, 8, 9]
Index of 9: 8
Count of 1: 1
After sort: [1, 2, 3, 4, 4, 5, 8, 9, 10]
After reverse: [10, 9, 8, 5, 4, 4, 3, 2, 1]
Copied list: [10, 9, 8, 5, 4, 4, 3, 2, 1]
After clear: []
Length of list: 0
Length of copied list: 9
Maximum: 10
Minimum: 1
Sum: 46
```

**What each line does:**

| Operation | Code | Result after running it |
|---|---|---|
| Add one item to the end | `my_list.append(4)` | `[1, 2, 3, 1, 4, 5, 4]` |
| Add several items to the end | `my_list.extend([8, 9, 7])` | `[1, 2, 3, 1, 4, 5, 4, 8, 9, 7]` |
| Insert at a specific position | `my_list.insert(0, 10)` | `[10, 1, 2, 3, 1, 4, 5, 4, 8, 9, 7]` |
| Remove the **first** matching value | `my_list.remove(1)` | `[10, 2, 3, 1, 4, 5, 4, 8, 9, 7]` |
| Remove and **return** the last item | `popped_element = my_list.pop()` | returns `7`; list becomes `[10, 2, 3, 1, 4, 5, 4, 8, 9]` |
| Find a value's position | `my_list.index(9)` | `8` |
| Count how many times a value appears | `my_list.count(1)` | `1` |
| Sort in place | `my_list.sort()` | `[1, 2, 3, 4, 4, 5, 8, 9, 10]` |
| Reverse in place | `my_list.reverse()` | `[10, 9, 8, 5, 4, 4, 3, 2, 1]` |
| Make an independent copy | `copied_list = my_list.copy()` | `[10, 9, 8, 5, 4, 4, 3, 2, 1]` |
| Empty the list | `my_list.clear()` | `[]` |

- `len()`/`max()`/`min()`/`sum()` on the untouched `copied_list` are **functions**, not methods — see §5 for exactly why that distinction matters.

## 2. Tuple operations (`2-tuple-ops.py`) — immutable, so far fewer methods exist

**Complete script:**
```python
my_tuple = (3, 1, 4, 1, 5, 9, 2, 6, 5)

count_of_1 = my_tuple.count(1)
print("Count of 1:", count_of_1)

index_of_9 = my_tuple.index(9)
print("Index of 9:", index_of_9)

print("Length:", len(my_tuple))
print("Max:", max(my_tuple))
print("Min:", min(my_tuple))
print("Sum:", sum(my_tuple))

sorted_list = sorted(my_tuple)
print("Sorted tuple as list:", sorted_list)

sorted_list.append(4)
print("After append:", sorted_list)

my_tuple.append(4)  # This will raise an AttributeError since tuples are immutable
print("After append:", my_tuple)
```

**Sample output:**
```
Count of 1: 2
Index of 9: 5
Length: 9
Max: 9
Min: 1
Sum: 36
Sorted tuple as list: [1, 1, 2, 3, 4, 5, 5, 6, 9]
After append: [1, 1, 2, 3, 4, 5, 5, 6, 9, 4]
Traceback (most recent call last):
  ...
AttributeError: 'tuple' object has no attribute 'append'
```

**What's happening:**

| Operation | Code | Result |
|---|---|---|
| Count occurrences | `my_tuple.count(1)` | `2` |
| Find a value's position | `my_tuple.index(9)` | `5` |
| Length | `len(my_tuple)` | `9` |
| Maximum | `max(my_tuple)` | `9` |
| Minimum | `min(my_tuple)` | `1` |
| Sum | `sum(my_tuple)` | `36` |
| Sort (returns a new **list**, doesn't touch the tuple) | `sorted_list = sorted(my_tuple)` | `[1, 1, 2, 3, 4, 5, 5, 6, 9]` |

- `sorted_list.append(4)` **works fine** — `sorted()` handed back a plain `list`, and lists are mutable. Result: `[1, 1, 2, 3, 4, 5, 5, 6, 9, 4]`.
- `my_tuple.append(4)` **crashes the script right there** — tuples have no `.append()` method at all, so the last `print` line never runs.
- ⚠️ **Tuples simply don't have `append()`/`remove()`/`pop()`/etc.** — not because they're blocked, but because those methods were never defined for the tuple type in the first place, since a tuple is meant to never change after creation.

## 3. Set operations (`3-set-ops.py`)

**Complete script:**
```python
my_set = {1, 2, 1, 3, 4, 5}

my_set.add(6)
print("After add:", my_set)

my_set.remove(2)
print("After remove:", my_set)

popped = my_set.pop()
print("Popped:", popped)
print("After pop:", my_set)

my_set.clear()
print("After clear:", my_set)

set_a = {1, 2, 3}
set_b = {3, 4, 5}

print("Union:", set_a.union(set_b))
print("Intersection:", set_a.intersection(set_b))
print("Difference:", set_a.difference(set_b))
```

**Sample output** (`my_set = {1, 2, 1, 3, 4, 5}` auto-dedupes to `{1, 2, 3, 4, 5}` on creation; exact element order is never guaranteed — see the warning below):
```
After add: {1, 2, 3, 4, 5, 6}
After remove: {1, 3, 4, 5, 6}
Popped: 1
After pop: {3, 4, 5, 6}
After clear: set()
Union: {1, 2, 3, 4, 5}
Intersection: {3}
Difference: {1, 2}
```

**What's happening:**

| Operation | Code | Result |
|---|---|---|
| Add one element | `my_set.add(6)` | now contains `6` too |
| Remove a specific element | `my_set.remove(2)` | `2` is gone |
| Remove and return an arbitrary element | `popped = my_set.pop()` | removes *some* element — sets have no order, so you can't predict which one |
| Empty the set | `my_set.clear()` | `set()` (empty) |
| Combine two sets | `set_a.union(set_b)` | every element from both: `{1, 2, 3, 4, 5}` |
| Only shared elements | `set_a.intersection(set_b)` | `{3}` |
| Only in `set_a`, not `set_b` | `set_a.difference(set_b)` | `{1, 2}` |

- ⚠️ **A set's printed order is never guaranteed** — don't rely on the order you happen to see in one run; two runs (or two machines) can legitimately print the same set's contents in a different order. The output above is one realistic example, not a promise of what you'll always see.

## 4. Dictionary operations (`4-dict-ops.py`)

**Complete script:**
```python
my_dict = {
    "name": "Madhu",
    "phone": "7396627149",
    "city": "Hyderabad",
}

print("Name:", my_dict['name'])

name = my_dict.get('name', 'Not Available')
print("Name:", name)

salary = my_dict.get('salary', 'Not Available')
print("Salary:", salary)

my_dict['occupation'] = 'SRE Engineer'
print("After adding occupation:", my_dict)

popped_value = my_dict.pop('phone')
print("Popped:", popped_value)
print("After pop:", my_dict)

print("Keys:", list(my_dict.keys()))
print("Values:", list(my_dict.values()))
print("Items:", list(my_dict.items()))

my_dict.clear()
print("After clear:", my_dict)

new_dict = {'a': 1, 'b': 2}
copied_dict = new_dict.copy()
print("Copied:", copied_dict)
```

**Sample output:**
```
Name: Madhu
Name: Madhu
Salary: Not Available
After adding occupation: {'name': 'Madhu', 'phone': '7396627149', 'city': 'Hyderabad', 'occupation': 'SRE Engineer'}
Popped: 7396627149
After pop: {'name': 'Madhu', 'city': 'Hyderabad', 'occupation': 'SRE Engineer'}
Keys: ['name', 'city', 'occupation']
Values: ['Madhu', 'Hyderabad', 'SRE Engineer']
Items: [('name', 'Madhu'), ('city', 'Hyderabad'), ('occupation', 'SRE Engineer')]
After clear: {}
Copied: {'a': 1, 'b': 2}
```

**What's happening:**

| Operation | Code | Result |
|---|---|---|
| Read a value by key (square brackets) | `my_dict['name']` | `'Madhu'` |
| Read the same key, safely, via `.get()` with a fallback | `my_dict.get('name', 'Not Available')` | `'Madhu'` — the fallback isn't used, since `'name'` exists |
| Read a missing key, with a fallback | `my_dict.get('salary', 'Not Available')` | `'Not Available'` — the fallback *is* used, since `'salary'` doesn't exist |
| Add/update a key | `my_dict['occupation'] = 'SRE Engineer'` | key added |
| Remove a key, and get its value back | `popped_value = my_dict.pop('phone')` | returns `'7396627149'` |
| List all keys | `list(my_dict.keys())` | `['name', 'city', 'occupation']` |
| List all values | `list(my_dict.values())` | `['Madhu', 'Hyderabad', 'SRE Engineer']` |
| List all key-value pairs | `list(my_dict.items())` | `[('name', 'Madhu'), ('city', 'Hyderabad'), ('occupation', 'SRE Engineer')]` |
| Empty the dict | `my_dict.clear()` | `{}` |
| Make an independent copy (on a fresh dict) | `copied_dict = new_dict.copy()` | `{'a': 1, 'b': 2}` |

- The two `.get()` calls side by side are the real teaching point here: same method, same syntax — one finds its key and returns the real value, the other doesn't and falls back to the default, **neither one crashes.**

- ⚠️ `my_dict['salary']` (square-bracket access on a missing key) would **crash** with `KeyError: 'salary'` — that's exactly why `.get('salary', 'Not Available')` is the safer way to read a key that might not exist.
- Unlike a set, a **dict's order is reliable** — Python guarantees (since 3.7) that a dict remembers the order keys were inserted in.

## 5. Functions vs Methods — the distinction that actually matters

### What is a function?
- A standalone block of code, **not tied to any object.**
- Takes data as an argument.
- Returns a result.
- Called like: `function_name(data)`.
- Examples already used above: `len(my_list)`, `max(copied_list)`, `sum(copied_list)`.

### What is a method?
- A function that **belongs to an object.**
- Defined inside that object's class.
- Called like: `object.method(arguments)` — the object comes first, joined with a dot.
- Examples already used above: `my_list.append(4)`, `my_list.sort()`, `my_dict.get('phone')`.

### Why `append()` is not a function
```python
append(my_list, 4)   # ❌ invalid — Python has no standalone append() function
```
`append` only exists as a **method defined inside the list class** — there's no free-floating `append()` function to call it as. The only correct form is:
```python
my_list.append(4)    # ✅ correct
```

### Why `len()` is not a method
```python
my_list.len()   # ❌ invalid — lists don't have a .len() method
```
`len()` is a **built-in function**, not something that belongs to the list object. The only correct form is:
```python
len(my_list)    # ✅ correct
```

### Side by side

| Feature | Function | Method |
|---|---|---|
| Belongs to an object | No | Yes |
| Called as | `function(x)` | `x.method()` |
| Defined in | Global scope / a module | Inside a class |
| Needs the object | Passed in as an argument | Implicit (it's the thing before the dot) |
| Example | `len(x)` | `x.append(4)` |

**Easy memory trick:** `object.something()` → it's a **method**. `something(object)` → it's a **function**.

### Why Python has both
- **Functions** are generic — they work across many different data types (`len()` works on a list, a string, a dict, a tuple — anything with a length).
- **Methods** are specific to one particular data type, and know how to modify or act on that exact kind of object (`list.append()` only makes sense for a list; `str.upper()` only makes sense for a string).

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| List methods | `append`/`extend`/`insert`/`remove`/`pop`/`sort`/`reverse`/`copy`/`clear` | Managing a list of server IPs as the cluster changes |
| Tuple | Has `count()`/`index()` only — no methods that modify it | Crashes with `AttributeError` if you try `.append()` |
| Set | `add`/`remove`/`pop`/`clear`, plus `union`/`intersection`/`difference` | Order is never guaranteed — don't rely on it |
| Dict | `.get(key, default)` avoids a `KeyError` on a missing key | Reading an optional config value with a sane fallback |
| Function vs Method | `object.something()` = method; `something(object)` = function | `my_list.append(4)` vs `len(my_list)` |
