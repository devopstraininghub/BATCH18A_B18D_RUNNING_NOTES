## 1. Opening a file — `open()` and its modes

- `open()` is the function used to open a file, before reading or writing it.

| Mode | Meaning |
|---|---|
| `'r'` | Read mode (default) |
| `'w'` | Write mode — creates a new file, or **overwrites** an existing one |
| `'a'` | Append mode — adds data at the end, keeps existing content |
| `'x'` | Create mode — fails if the file already exists |
| `'b'` | Binary mode |
| `'t'` | Text mode (default) |
| `'+'` | Read **and** write mode |

```python
file = open("devops_b17.txt", "a")
```

## 2. Reading and overwriting a file — manual open/close (`5-file.py`)

```python
file = open("devops", "r")
content = file.read()
print(content)
file.close()


file = open("devops", "w")
file.write("Hi , AWS DEVOPS IS SUPER CRAZY.. but python is little tricky \n")
file.close()

file = open("devops", "r")
content = file.read()
print(content)
file.close()
```
- The **first** read prints whatever `devops` already contained from an earlier run.
- `open(..., "w")` then **overwrites** the entire file with just the one new line — none of the old content survives.
- The **second** read confirms the overwrite.

**Sample output** (`devops` already existed with some prior content before this run):
```
<whatever devops contained before this run>
Hi , AWS DEVOPS IS SUPER CRAZY.. but python is little tricky 

```
- ⚠️ Every `open()` call here needs its own `file.close()` — forget one, and the file can stay locked, or writes can be lost if the program ends before the data is actually flushed to disk. This is exactly the manual-cleanup risk §4's `with` statement exists to remove.

## 3. Reading and appending — the `with` statement (`6-file.py`)

```python
with open("testfile", "r") as file:
    content = file.read()
    print(content)


with open("testfile", "a") as file:
    file.write("Hi , AWS DEVOPS IS SUPER CRAZY\n")


with open("testfile", "r") as file:
    content = file.read()
    print(content)
```
- The first `with` block reads and prints whatever `testfile` already contained (e.g. a line like `"HI, WELCOME TO MINDCIRCUIT"` from an earlier run).
- `'a'` mode then **adds** the new line at the end — the existing content stays untouched.
- The final `with` block reads the file again, now showing both the old line and the newly appended one.

**Sample output** (`testfile` already contained `"HI, WELCOME TO MINDCIRCUIT"` before this run):
```
HI, WELCOME TO MINDCIRCUIT

HI, WELCOME TO MINDCIRCUIT
Hi , AWS DEVOPS IS SUPER CRAZY
```
- No `file.close()` anywhere in this version — `with` closes each file automatically the moment its indented block ends, even if an error happens partway through.

## 4. Closing a file — manual vs `with`, side by side

| | Manual (`5-file.py`'s style) | `with` (`6-file.py`'s style) |
|---|---|---|
| Closing | You must call `file.close()` yourself, every time | Happens automatically when the block ends |
| If an error happens mid-block | The file can stay open/locked | Still closes safely |
| Recommended? | Only for very short, simple scripts | Yes — the standard, idiomatic way |

## 5. Exception handling for file operations (`7-exceptionhandling.py`)

- File operations can fail for reasons outside your code's control:
  - `FileNotFoundError` — the file doesn't exist.
  - `PermissionError` — no access rights to the file.
  - `IOError` — a general input/output failure (an alias for `OSError` in Python 3).
  - Disk full — cannot write any more data.
  - Device not ready — e.g. a USB drive that isn't actually connected.
  - Hardware failure — bad sectors, other I/O issues.
- Catching these prevents the whole program from crashing, and lets you show a clear message instead of a raw traceback.

```python
try:
    with open("testfile", "r") as file:
        content = file.read()
        print(content)

except FileNotFoundError:
    print("File not found error occurred. Please check the file name and try again.")

except PermissionError:
    print("Permission error occurred. You do not have permission to access this file.")

except IOError:
    print("An I/O error occurred while trying to read the file.")

except Exception as e:
    print(f"An unexpected error occurred: {e}")
```
- The `except` blocks are checked **top to bottom**, same ordering rule as `if`/`elif` (`17.3November_Python_Conditionals.md`) — Python catches the **first** matching exception type.
- `except Exception as e:` at the end is a catch-all — it matches anything not already caught above, and `e` holds the actual error message.
- ⚠️ If `testfile` genuinely doesn't exist, this prints `File not found error occurred. Please check the file name and try again.` instead of crashing with an unhandled `FileNotFoundError` traceback.

**Easy memory trick:** `try` = attempt it. `except` = what to do if it fails. `with` = clean up automatically either way.

## Quick Recap Table

| Concept | One-line meaning | Real-time (DevOps) example |
|---|---|---|
| `open(path, mode)` | Opens a file in the given mode | `'r'`/`'w'`/`'a'` for read/overwrite/append |
| Manual open/close | You must call `file.close()` yourself | Risk: a forgotten `close()` can lose data or lock the file |
| `with open(...) as f:` | Opens a file and closes it automatically | The recommended way — safe even if an error happens |
| `'w'` vs `'a'` | Overwrite vs add to the end | Writing a fresh report vs appending to a log file |
| `try`/`except` | Attempt code, handle specific failures gracefully | Catching `FileNotFoundError` instead of crashing |
| `except Exception as e` | A catch-all for anything not already handled | Logging the real error message instead of losing it |
